# SRS — Требования к дельта-нейтральному боту на Bybit

Версия 1.0 · Фаза 0 · 2026-08-05
Входные документы: [PROJECT.md](../PROJECT.md), [DECISIONS.md](DECISIONS.md), [PARAMS-CONSERVATIVE.md](PARAMS-CONSERVATIVE.md), [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md)

## Как читать этот документ

Каждое требование имеет идентификатор, формулировку и **способ проверки** — без способа проверки требование не считается написанным. Приоритет требований: **RR (риск) > NFR (надёжность) > FR (функции)**. При конфликте побеждает требование с более высоким приоритетом; это не стилистическая оговорка, а правило разрешения споров при реализации.

Обозначения проверки: `unit` — автотест на моках, `integration` — testnet, `system` — полный контур, `manual` — ручная процедура с записью в PHASE-LOG, `review` — проверка кода или конфигурации.

Пометка **OPEN** означает параметр, не решённый владельцем. Код обязан читать его из конфигурации и **отказываться стартовать**, если значение не задано явно.

## 1. Границы системы

**В границах:** сбор рыночных данных Bybit; отбор пар спот+перп; расчёт размера; открытие и закрытие дельта-нейтральной пары; риск-контроль; сверка с биржей; kill switch трёх уровней; алерты и суточная сводка в Telegram.

**Вне границ:** cash-and-carry на квартальных фьючерсах (Фаза 5, требования будут дописаны отдельно); любая направленная торговля; копирование чужих сделок; вывод средств; торговля более чем на одной бирже; веб-интерфейс управления.

**Явно отвергнуто с обоснованием:** исследовательский трек по лидерборду. У Bybit V5 нет документированного публичного эндпоинта лидерборда — это был бы веб-скрейпинг с риском бана IP, а IP у нас в белом списке API-ключа. Стоимость не нулевая, ожидаемая ценность близка к нулю.

## 2. Риск-требования (RR) — высший приоритет

### 2.1. Секреты

| ID | Требование | Проверка |
|---|---|---|
| RR-01 | API-ключ не имеет права Withdrawal. Бот при старте запрашивает права ключа и **отказывается работать**, если Withdrawal разрешён | integration |
| RR-02 | Секреты читаются только из переменных окружения. `.env` в `.gitignore` с первого коммита | review + unit (тест, падающий при наличии секрета в трекаемых файлах) |
| RR-03 | Секрет не попадает ни в один лог, ни в текст ошибки, ни в stack trace. Все ошибки клиента Bybit проходят через нормализатор, вычищающий `requestOptions` | unit: замокать не-2xx ответ, проверить сериализованный лог на отсутствие подстроки секрета |
| RR-04 | Диагностические отчёты Node не содержат окружения: `process.report.excludeEnv = true` устанавливается до любой другой инициализации | unit + review |
| RR-05 | Testnet и mainnet используют разные переменные окружения. При старте бот сверяет заявленное окружение с фактическим хостом API и **отказывается стартовать** при несовпадении | unit + integration |
| RR-06 | Ключ привязан к белому списку IP. Процедура и напоминание о трёхмесячном сроке без привязки — в RUNBOOK | manual |

### 2.2. Целостность позиции

| ID | Требование | Проверка |
|---|---|---|
| RR-10 | Обе ноги или ни одной. При неудаче второй ноги первая закрывается автоматически и немедленно, без ожидания следующего цикла | unit + integration |
| RR-11 | Каждый ордер отправляется с уникальным `orderLinkId`, детерминированно выводимым из намерения. Повторная отправка того же намерения использует **тот же** идентификатор | unit |
| RR-12 | Намерение открыть/закрыть ногу записывается в БД **до** отправки в сеть. Восстановление после сбоя опирается на журнал намерений, а не на память процесса | unit + system (SIGKILL между записью и отправкой) |
| RR-13 | При таймауте или сетевой ошибке состояние ордера выясняется запросом по `orderLinkId`, а не повторной отправкой. Повторная отправка допустима только после подтверждения, что ордера не существует | unit + integration |
| RR-14 | Биржа — единственный источник истины. Перед любым действием, меняющим позицию, состояние подтверждается запросом к бирже | review + unit |
| RR-15 | Остаточная дельта после исполнения вычисляется и сравнивается с допуском. У спота и перпа разные шаги лота (у BTCUSDT 0.000001 против 0.001), поэтому точное равенство ног невозможно и допуск обязателен | unit |
| RR-16 | Частичное исполнение любой ноги переводит позицию в состояние, требующее выравнивания, а не считается успехом | unit + integration |
| RR-17 | Одновременная работа двух экземпляров бота исключена механизмом взаимного исключения. Второй экземпляр завершается с ошибкой, не выполнив ни одного действия | unit + system |

### 2.3. Лимиты риска

| ID | Требование | Проверка |
|---|---|---|
| RR-20 | Эффективное плечо = номинал шорта / total equity. Целевое 1.0x, жёсткий потолок **1.5x**. Расчёт покрыт тестами, включая краевые значения | unit |
| RR-20a | Дополнительно к RR-20: `accountMMRate` (общесчётная поддерживающая маржа) пересчитывается перед каждым входом через биржевой эндпоинт пред-расчёта IMR/MMR — не собственную реализацию маржинального движка. Вход отклонён при превышении `ACCOUNT_MMR_MAX` (старт 0.30). Обоснование в RISK-REGISTER.md FM-25: ликвидация в UTA происходит по счёту целиком, RR-20 её не покрывает | unit + integration |
| RR-21 | Максимум 25% общего капитала в одной монете, считая по номиналу спотовой ноги | unit |
| RR-22 | Одновременных позиций не более **1** до закрытия Фазы 4 | unit |
| RR-23 | Инструмент допускается, только если `turnover24h` перпа ≥ 100 млн USDT **и** спота ≥ 20 млн USDT | unit |
| RR-24 | Символы Innovation Zone и Adventure Zone исключены полностью. Категория читается из данных инструмента, а не из захардкоженного списка | unit + integration |
| RR-25 | Вход разрешён, только если полный круг комиссий окупается за ≤ 3 суток при текущем funding **и** funding-ставка не является артефактом клампинга по полу/капу (`isPremiumDriven`: premium index, нормализованный к 8ч, должен превышать +0.05%). Круг считается по всем четырём ногам, базису, оценке проскальзывания на **обеих** книгах (RR-23) и стоимости заимствования, если она ненулевая (RR-25a) | unit — включая тест RISK-REGISTER.md FM-01: положительный net P&L на бэктесте при пороге 0.020%/8h, отрицательный при 0.010%/8h |
| RR-25a | Ожидаемый чистый доход `r_net = r8h − borrowCost8h` обязан быть учтён в проверке окупаемости. См. RISK-REGISTER.md FM-09: стоимость заимствования USDT (≈3.86% APR на VIP0) сопоставима с реализованной средней доходностью мажоров и может делать позицию убыточной ещё до открытия | unit |
| RR-26 | Ставки комиссий читаются из `/v5/account/fee-rate` при старте. Захардкоженные VIP 0 используются только как fallback и логируются как таковые | unit + integration |
| RR-27 | Проскальзывание сверх 0.05% на ногу — отказ от входа, а не исполнение по худшей цене | unit |
| RR-28 | Модуль `risk/` имеет право вето на любое решение `strategy/`. Обойти его технически невозможно: `strategy/` не имеет доступа к `execution/` | review + архитектурный тест зависимостей |
| RR-29 | Никакого усреднения, докупок в убыток и увеличения существующей позиции. Отсутствие такой операции в API модуля исполнения | review + unit |

### 2.4. Kill switch

| ID | Требование | Проверка |
|---|---|---|
| RR-30 | Kill switch реализован и протестирован **до** написания логики входа в позицию | manual, фиксируется в PHASE-LOG |
| RR-31 | Уровень 1 (ручной стоп) работает из отдельного процесса. Зависший торговый цикл не может опрашивать Telegram, поэтому стоп внутри торгового процесса не считается kill switch'ем | system: заблокировать главный цикл, проверить срабатывание |
| RR-32 | Уровень 1 доступен двумя независимыми путями: команда в Telegram и файл-флаг на диске | system |
| RR-33 | Команды Telegram принимаются только от авторизованных `chat_id`: главный админ (`TELEGRAM_CHAT_ID` из `.env`, неизменен) плюс белый список в таблице `authorized_users` (БД), которым управляет только главный админ через `/add`/`/delete`. Все прочие отвергаются и логируются | unit |
| RR-34 | Уровень 2 различает **закрытие** и **заморозку** по каждому триггеру согласно таблице §2.5 | unit |
| RR-35 | Уровень 3: heartbeat раз в минуту во внешний сервис, живущий вне VPS бота. Watchdog на том же хосте не удовлетворяет требованию | system + manual |
| RR-36 | Канал алертов watchdog независим от основного: отдельный бот с другим токеном | manual |
| RR-37 | Отказ самого kill switch'а обнаруживается: если команда стопа не подтверждена исполнением за N секунд, супервизор закрывает позиции принудительно | system |
| RR-38 | Kill switch проверен вручную не менее 5 раз в разных состояниях перед закрытием Фазы 3 | manual |

### 2.5. Матрица реакции уровня 2

| Триггер | Реакция | Обоснование |
|---|---|---|
| Просадка от пика выше 3% | Закрыть всё по рынку, стоп до ручного рестарта | Состояние известно |
| Маржа шорта ниже порога | Закрыть всё по рынку немедленно, приоритет выше всех | Промедление = ликвидация |
| Одна нога открыта, вторая не встала | Немедленно закрыть оставшуюся | RR-10 |
| Локальное состояние разошлось с биржей | **Заморозка** + алерт, полная сверка, решение за владельцем | Бот не знает, что открыто; слепое закрытие само создаёт голую ногу |
| `accountMMRate` превысил тревожный порог (RR-20a) | Закрыть по рынку пару, потребляющую больше всего маржи, не всё сразу | RISK-REGISTER.md FM-25: ликвидация в UTA Cross Margin происходит на уровне счёта и продаёт спот-обеспечение любой позиции, а не только проблемной — правило «25% на монету» даёт диверсификацию возможностей, но не изоляцию риска |
| Интервал фандинга удерживаемого символа изменился (например с 8ч на 1ч) | Закрыть эту пару по рынку | RISK-REGISTER.md FM-04: Bybit переключает символ на часовой сеттлмент, когда ставка упирается в свой кап, без предварительного уведомления — это происходит именно при экстремальных ставках |
| M ошибок API подряд (старт M = 5) | **Заморозка.** Если позиция открыта и ошибки идут вдвое дольше — попытка закрытия с ретраями | Каскад может быть баном по rate limit; долбить биржу опасно |
| Нет данных WS дольше T (старт 30 с) | **Заморозка** + переход на REST-поллинг. Если и REST мёртв дольше T2 (300 с) — закрытие при первой возможности | Потеря WS — потеря зрения, не потеря позиции |

### 2.6. Просадка

| ID | Требование | Проверка |
|---|---|---|
| RR-40 | Просадка считается от total equity аккаунта, включая нереализованный P&L обеих ног | unit |
| RR-41 | Пик фиксируется за всё время работы, переживает перезапуск, хранится в БД | unit + system |

### 2.7. Обработка ошибок

| ID | Требование | Проверка |
|---|---|---|
| RR-50 | Ни одного проглоченного исключения. Непонятая ошибка = остановка + алерт | review + unit |
| RR-51 | Клиент Bybit работает с `throwExceptions: true` **и** дополнительной явной проверкой `retCode !== 0`. Библиотечный дефолт `false` резолвит промис при ошибке — это молчаливый провал | unit: замокать `retCode 110007`, убедиться, что промис отклонён |
| RR-52 | Все входящие сообщения WebSocket валидируются схемой на границе. Библиотека типизирует полезную нагрузку как `any`, компилятор здесь не помогает | unit |
| RR-53 | Все ошибки классифицируются: временная (ретрай), постоянная (стоп), неизвестная (стоп + алерт). Неизвестная никогда не трактуется как временная | unit |

## 4. Нефункциональные требования (NFR)

| ID | Требование | Проверка |
|---|---|---|
| NFR-01 | Точная десятичная арифметика на всём пути денег. Float запрещён в JSON-разборе, в вычислениях и в схеме БД | unit + тест схемы, падающий при появлении float-колонки |
| NFR-02 | Деньги в Postgres — `numeric` **без** указания точности и масштаба: `numeric(p,s)` молча округляет лишние знаки | review + unit |
| NFR-03 | Числа не хранятся внутри jsonb: драйвер разбирает jsonb как JSON и превращает их в float | review |
| NFR-04 | Клиентский rate limiter: не более 600 запросов / 5 с на IP; per-UID лимиты по эндпоинтам соблюдаются. Заголовки лимитов читаются и логируются | unit + integration |
| NFR-05 | Таймаут HTTP-запроса задан явно. Библиотечный дефолт — 5 минут, для торгового пути неприемлемо | review |
| NFR-06 | Реконнект WebSocket с экспоненциальным backoff, джиттером и потолком. Встроенный механизм использует фиксированные 500 мс без потолка | unit |
| NFR-07 | Обнаружение «тихой смерти» WebSocket: сокет открыт, данных нет. Детектор по отсутствию сообщений, а не по состоянию сокета | unit |
| NFR-08 | Graceful shutdown: завершение текущей операции, отсутствие частичных записей, корректное закрытие соединений | system |
| NFR-09 | Автоперезапуск с тормозом против crash-loop. Бот, падающий после первой ноги и рестартующий каждые 100 мс, за минуту насыпет сотни попыток ордеров. Требуется ограничение частоты рестартов с переходом в состояние отказа и алертом | system |
| NFR-10 | Часы синхронизированы NTP. Перекос часов ломает подпись запросов | manual + мониторинг |
| NFR-11 | Весь код Bybit изолирован в модуле `exchange/`. Прямые вызовы библиотеки из бизнес-логики запрещены — это цена замены библиотеки, если её забросят | архитектурный тест зависимостей |
| NFR-12 | Версии Node, Postgres и расширений зафиксированы. Node 22 LTS: поле `engines` в клиентской библиотеке отсутствует, Node 24 не тестировался никем | review |
| NFR-13 | Всё, что касается денег, покрыто тестами: расчёт размера, расчёт окупаемости, проверки риска | review + отчёт покрытия |
| NFR-14 | Ротация логов настроена так, чтобы разбор ночного инцидента был возможен утром | manual |
| NFR-15 | Ежедневный бэкап БД в место, не совпадающее с VPS бота | manual |
| NFR-16 | Восстановление после сбоя не требует ручного разбора БД: бот сам определяет своё состояние по журналу намерений и сверке с биржей | system |

## 5. Внешние ограничения

| ID | Ограничение | Следствие |
|---|---|---|
| C-01 | Спот и перп нельзя открыть одной атомарной операцией: `category` — скаляр на запрос, батчи неатомарны | Разрыв между ногами существует всегда. Вся конструкция RR-10 нужна именно поэтому |
| C-02 | `orderLinkId` — идемпотентность по факту, но не по контракту: дубликат отклоняется (`110072` деривативы, `170141` спот), но Bybit не публикует ни окна уникальности, ни срока хранения | Принятый риск, см. §6 |
| C-03 | Размещение ордера асинхронно: подтверждение приёма не означает финального состояния | Обязательна дополнительная проверка состояния |
| C-04 | В обычном cross-режиме спот засчитывается залогом с дисконтом, но начальную маржу шорта не снижает | Плечо считаем от equity, а не от «свободной» маржи |
| C-05 | Portfolio margin со Spot Hedging даёт взаимозачёт, но `/v5/position/list` перестаёт отдавать `liqPrice`, `positionIM`, `positionMM` | Режим отвергнут: слепота по цене ликвидации несовместима с RR-14 |
| C-06 | Актив в спотовом кошельке засчитывается залогом только при включённом флаге «Used As Collateral», и с дисконтом | Проверять фактически, не предполагать |
| C-07 | `/v5/market/funding/history` — 200 записей за запрос, курсора нет, пагинация только назад по `endTime` | Глубина бэкфилла ограничена; выполнимость проверить до планирования сроков Фазы 1 |
| C-08 | Превышение лимита запросов — 403 и бан не менее 10 минут | Бан во время открытой позиции = слепота. Лимитер обязателен, а не желателен |

## 6. Принятые риски — механизма в коде нет

| ID | Риск | Почему принят |
|---|---|---|
| AR-01 | Риск самой биржи: средства на Bybit юридически не принадлежат владельцу | Митигации в коде не существует. Ограничивается только размером капитала на бирже |
| AR-02 | ADL: биржа может закрыть шорт принудительно | Предотвратить нельзя. Можно только обнаружить быстро — FR-305 |
| AR-03 | `orderLinkId` без опубликованного контракта идемпотентности | Альтернативы нет. Поведение зафиксировать тестом на testnet и перепроверять при обновлениях API |
| AR-04 | Библиотека `bybit-api` неофициальная; в её зависимостях `isomorphic-ws`, не публиковавшийся с 2022 года, прямо на пути WebSocket | Изоляция в `exchange/` (NFR-11) ограничивает стоимость замены |
| AR-05 | Telegram — сторонняя зависимость в контуре безопасности | Смягчается файлом-флагом как вторым путём (RR-32) и независимым каналом watchdog (RR-36) |
| AR-06 | Все факты об API получены чтением документации, не экспериментом | Закрывается на Фазе 3 обязательным прогоном поведенческих проверок |
